# Co-op: what the lead does at release

1. **Merge** `claude/skotos-coop` (from 564162f). Files of mine only: `src/net/*`, `src/ui/coopui.js`, `tools/net/*`, `tools/coop.mjs`, `docs/coop/*`. The hooks in shared files are small and listed at the end of `README.md`; on a conflict keep both sides' lines.
2. **Publish with the capabilities** (the same artifact URL):
   ```js
   capabilities: {
     room: { topics: { s: 'interact', w: 'interact', i: 'interact', f: 'interact', c: 'interact' } },
     user: { scopes: ['profile'] }
   }
   ```
   A non-empty `capabilities` is the whole set: if the artifact declares anything else by then, list it too.
3. **Check** on the published page: one signed-in browser hosts (Co-op → Host a game), another account with Contributor access joins by the code; a Viewer opens Co-op and is told why it plays alone, with no Host or Join; a signed-out or public-link view has no Co-op at all (the title, the pause menu and the HUD as in single-player); the strict-CSP check as usual (the co-op code makes no other connection: everything goes through `claude.use('room')` and `claude.use('user')`).
4. **Tell the owner** how to invite a friend: Share → invite at Contributor (or Editor); the friend opens the link signed in, picks a hero, Co-op, enters the code.
5. **Later, the Android app / a public web build (Supabase): built, not yet run on a project.** Everything is in `docs/coop/supabase.md`: why the server must say who sent each message, setting up a project from zero, the costs and limits, and what is not verified. In short:
   - A guest trusts its host's messages because the artifact's room stamps who sent them; Realtime does not, so on Supabase no page broadcasts on the game's channels. Each tab signs in anonymously, joins private channels (`skotos:<room>`), and says everything through `skotos.send`, a `SECURITY DEFINER` RPC that checks the caller, the topic, the size (4 KiB) and the rate (40 a second) and broadcasts it with the caller's id written by the server (`_by`). `SupabaseTransport` (`stamped`) takes a peer from that and nothing else; who hosts a game is the server's `skotos.games` row, never presence. `pickTransport` still takes Supabase only with `stamped: true`.
   - The migration is `supabase/migrations/20261026120000_skotos_coop.sql` (its own schema `skotos`, policies only on `skotos:` topics). The project needs anonymous sign-ins allowed and the schema `skotos` exposed to the Data API. `npm run build:web` builds `dist-web/` with supabase-js (2.117.3) and the project from `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`; the artifact build carries none of it.
   - **What it costs.** A party of four is about 52 messages a second and, the database's broadcasts reaching their senders too, about 280 Realtime events a second (with client broadcasts it was 210-225); the lobby is as before (twelve hosts among 48 pages, about 59). Per second the Free plan (100) holds one pair and no party of four, Pro (500) one party of four, Pro without the spend cap (2,500) about eight. Per month the Free plan's 2 million messages are about 2 hours of one party of four, Pro's 5 million about 5, then about $2.50 an hour of a party of four ($2.50 a million). Every message is also a row in `realtime.messages` for three days, about 1.8 times its JSON: 150-250 MB an hour of a party of four, so the Free plan (500 MB) turns read-only after two or three hours of play within three days. Choose the plan for the parties expected before opening the build; nothing in the game can hold a project-wide limit.
   - **Realtime's rates.** A client may call `track()` only 5 times in 30 s (past that Realtime shuts the channel, broadcast and all): `SupabaseTransport` tracks once a channel and sends the game's presence as a message (`_p`), so that holds whatever the game does. A page with nothing to show in the lobby sends nothing there.
   - **Before opening the build**: apply the migration, turn on anonymous sign-ins, expose `skotos`, run the checks of `supabase.md` (the project's postgres must pass row level security in `realtime.send`, or every send is lost without an error), and play a game on the project; then choose where `dist-web/` is hosted.
   (`tools/net/test-transport.mjs` shows a forged sender refused on the stamped path, a guest unable to claim the host, the rate and the cap, and still a forged sender heard as named on the unstamped one, which `pickTransport` refuses; `tools/net/test-migration.mjs` runs the migration on PGlite against Realtime's own `realtime.send` and join check.)
6. **Tests to run after a merge**: `node tools/net/test-transport.mjs`; `node tools/coop.mjs join|pack|loot|revive|churn|hostleave|cheat|act5|four|bosses|room|ui|ux|access <out>` against a private no-HMR server (`BASE=http://localhost:<port>/`).
